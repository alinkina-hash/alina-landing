## Задача 6: Make.com — Сценарий 1 «Новая запись Cal.com» (реальная архитектура, не совпадает с первоначальным планом ниже)

**Что делает:** единый сценарий на один вебхук от Cal.com, разбирает 4 типа событий через Router, для каждого — своя ветка обработки в Notion + Telegram.

> Актуальная схема сложнее исходного черновика (ниже сохранён для истории, но не отражает реальность). Реальная структура зафиксирована по состоянию на 2026-08-20:

**Триггер:** Webhooks → Custom webhook (модуль 2) → **Router 4**, ветки по `triggerEvent`:
- 1st: `BOOKING_CREATED`
- 2nd: `BOOKING_CANCELLED`
- 3rd: `BOOKING_RESCHEDULED`
- 4th: `MEETING_ENDED`
- 5th: зарезервирована, не используется

**✅ Ветка BOOKING_CREATED — готово и проверено:**
- Notion 16 (Search Objects, база Клиенты, фильтр Email = `2.payload.attendees[].email`) → **Router 9**:
  - **1st «Клиент найден»** → Notion 10 (Create a Data Source Item, база Сессии; Клиент = `16.Page ID`; Кабинет = `16.Properties Value.Кабинет[].ID`; Include Time = Yes) → **Router 30**:
    - путь 1: фильтр «Клиент уже писал боту» (`16.Properties Value.Telegram Chat ID` Exists) → Telegram Bot 26 (Send a Text Message, клиенту)
    - путь 2 (без фильтра): Telegram Bot 29 (Send a Text Message, тебе)
  - **2nd «Новый клиент»** → Notion 11 (создаёт клиента в Клиенты) → Notion 12 (создаёт кабинет в Кабинеты, Клиент (связь) = `11.Database Item ID`) → Notion 13 (создаёт сессию, Клиент = `11.Database Item ID`, Кабинет = `12.Database Item ID`, Include Time = Yes) → **Router 33**:
    - путь 1: фильтр «Клиент уже писал боту» (`11.Properties Value: Telegram Chat ID` Exists) → Telegram Bot 31 (клиенту; Chat ID почти всегда пуст сразу после создания — фильтр защищает от ошибки, реальное сообщение уйдёт позже через отдельный сценарий /start)
    - путь 2 (без фильтра): Telegram Bot 32 (тебе)
    - Полностью готово 2026-08-21, симметрично ветке «Клиент найден»

**✅ Ветка BOOKING_CANCELLED — готово и проверено:**
- Notion 19 (Search Objects, база Сессии, фильтр Booking UID = `2.payload.uid`) → фильтр «Букинг существует?» (`19.bundle` Exists) → Notion 6 (Update a Data Source Item, только Статус = «Отменена»)
- [ ] Telegram-уведомления в этой ветке (клиенту об отмене, тебе) пока не добавлены — решить, нужны ли

**⬜ Ветка BOOKING_RESCHEDULED — не построена** (пустая заготовка на схеме)

**🔄 Ветка MEETING_ENDED — в процессе (решено 2026-08-21: сразу и метит «Проведена», и запрашивает фидбэк, объединяя с Задачей 8, часть A):**
- Notion 8 (Search Objects, база Сессии, фильтр Booking UID = `2.payload.uid`, limit 1) → фильтр «Букинг существует?» (`8.bundle` Exists) → Notion 34 (Update a Data Source Item, Data Source Item ID = `8.Page ID`, только Статус = «Проведена») → Notion 36 (Get a Data Source Item, action "Get By: Data Source", Data Source Item ID = `8.Клиент[].ID` — получает карточку клиента этой сессии по relation, без Search/фильтра, т.к. Notion API не фильтрует по Page ID)
- [ ] **Заблокировано:** у модуля 36 (`Get a Data Source Item`) панель `Properties Value` пока пустая — Make ещё не видел реального бандла с этого действия, нужен хотя бы один реальный прогон, чтобы подтянулись названия полей (в т.ч. Telegram Chat ID)
- [ ] Тестируем через реальное тестовое бронирование на 1-2 минуты вперёд, ждём пока Cal.com сам пришлёт MEETING_ENDED (не мгновенно, в отличие от CREATED/CANCELLED) — в процессе, ждём результата
- [ ] После того как Properties Value подтянется: добавить финальный **Telegram Bot → Send a Text Message**, Chat ID = `36. Properties Value: Telegram Chat ID`, с фильтром Exists перед ним, текст: "Спасибо за сегодняшнюю сессию! 🙏 Оцени, пожалуйста, от 1 до 5 — как прошло?"
- [ ] Приём ответа клиента (цифра 1-5 + комментарий) — это **отдельный будущий сценарий** (Telegram → Watch Updates), не может быть частью этого сценария на вебхуке Cal.com. Соответствует Частям B/C Задачи 8 ниже — не начато.

## Итог

После выполнения всех задач система работает так:
1. Клиент записывается в Cal.com → ты и клиент получают уведомление в Telegram + сессия создаётся в Notion
2. За 24ч → автоматическое напоминание клиенту и тебе
3. Ты провела сессию → меняешь статус на «Проведена» → бот запрашивает фидбэк у клиента → оценка и комментарий сохраняются в Notion
4. Кабинет клиента: шаришь страницу Notion тем, кому нужен доступ
